## Story
As a developer, I want a runnable API project with a health endpoint and a test project, so that every later story has somewhere to add its code and its tests.

## Acceptance criteria
- **AC1** Given the API is running, when a client sends `GET /health`, then the response is 200 and the JSON body is `{"status":"Healthy"}`.
- **AC2** Given a clean clone and the .NET SDK version named in `docs/context/stack.md`, when `dotnet test` runs at the repository root, then it builds the API project and the test project through one solution file and exits 0.

## Out of scope
- Any endpoint other than `GET /health`.
- Database access, EF Core, migrations and Docker.
- Sign-in, authorisation, OpenAPI documents, logging and configuration beyond the framework defaults.
- The web UI.
- Workflow files under `.github/`. They change on a maintenance branch.
